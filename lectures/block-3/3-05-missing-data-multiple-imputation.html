Lecture 3.5

Missing data and multiple imputation

Block 3 · Biostatistics core
The point

Every real health dataset has holes, and the default in every package is to drop incomplete rows silently. Whether that is harmless depends on why values are missing and on what you estimate. Multiple imputation (MI) fixes many cases, but only if the imputation model contains the outcome, the right auxiliary variables and the study design. Project 3 starts after this lecture and needs all of it: missing urine and covariate values, survey weights, a survival outcome, and a sensitivity analysis for data that are missing for reasons you cannot see.

1. Why data are missing: MCAR, MAR, MNAR

The missingness mechanism is a claim about what predicts whether a value is missing; it decides which methods give unbiased answers.

What it is
MCAR (missing completely at random): missingness is unrelated to anything, observed or not. MAR (missing at random): missingness depends only on things you observed; among people with the same observed values, those missing are like those not missing. MNAR (missing not at random): missingness depends on the missing value itself, or on something unobserved related to it.
Why it matters
Complete-case analysis is safe under MCAR and in some MAR and MNAR cases (section 2). Standard MI assumes MAR. Under MNAR, no method using the observed data alone is guaranteed to work; you need assumptions and sensitivity analysis.
How to read it
MAR is conditional: it is true or false given the variables you use. Adding a variable that predicts missingness can turn MNAR into (approximately) MAR. You can show data are not MCAR (missingness predicted by observed variables), but no test can tell MAR from MNAR.
Trap

“Little’s test was non-significant, so data are MCAR.” The test only checks whether missingness relates to observed variables, often with little power. It says nothing about MNAR. Argue the mechanism from how the data were collected.

Analogy

Missing homework. The printer jammed at random: MCAR. Pupils with after-school jobs (which you know about) hand in less: MAR. Pupils who couldn’t do it don’t hand it in: MNAR, and the average of the handed-in work flatters the class.

2. When complete-case analysis is fine

For regression coefficients, complete cases are unbiased whenever missingness does not depend on the outcome once the model’s covariates are accounted for, even if it depends strongly on those covariates.

What it is
Complete-case analysis (CC) uses only rows with every analysis variable observed. A regression estimates the outcome’s distribution given the covariates. If being complete depends only on the covariates, CC changes which covariate values you see, not how the outcome behaves at each value, so the slope is unbiased.
Why it matters
This holds even when a covariate is missing because of its own value (formally MNAR), as long as that has nothing to do with the outcome. In that case CC is unbiased and standard MI, which assumes MAR, can be biased. For means and prevalences, by contrast, CC is biased whenever missingness relates to the variable, under MAR included.
How to read it
Ask one question: given the covariates in my model, does the chance of being complete depend on the outcome? If no, CC regression is unbiased (MI may still add precision). If yes, CC is biased and MI with good predictors of missingness may fix it. One exception for logistic regression: if missingness depends only on the outcome, odds ratios stay unbiased (the case-control logic); only the intercept is wrong.

MCAR, MAR, MNAR: complete cases versus imputation

Systolic BP depends on a covariate X in the analysis model; an auxiliary Z, not in that model, also tracks BP. About 40% of BP values go missing, driven by nothing (MCAR), by X, by Z, or by BP itself (MNAR). Raise the strength and compare complete-case and imputed estimates with the full data.

Example · Project 3

Suppose urine Na/K is missing more often in older participants. If age is in the Cox model, CC estimates of the Na/K hazard ratio are not biased by that. Now suppose it is missing more often in frail participants who skipped parts of the exam, and frailty is not in the model. Frailty predicts death, so missingness now depends on the outcome given the model’s covariates, and CC is biased. MI helps only if variables tracking frailty (self-rated health, prior cardiovascular disease, hospital use) are in the imputation model.

Trap

“MI is always better than complete cases.” If only the outcome is missing and there are no useful auxiliary variables, MI reproduces CC with extra noise. If missingness in a covariate depends on its own value but not the outcome, CC is unbiased and MI under MAR may not be. Choose by the mechanism, not by fashion.

3. Multiple imputation by chained equations

MI fills each hole several times with plausible values drawn from a model, analyses each completed dataset, and combines the results so the uncertainty about the missing values shows up in the standard errors.

What it is
MICE (also called fully conditional specification) imputes one variable at a time from a regression on all the others, cycles through the variables, and repeats until the draws settle. Run it to get m completed datasets that differ where data were missing. Predictive mean matching (PMM), the default for numbers, borrows an observed value from a donor with a similar prediction, so imputations stay realistic.
Why it matters
It handles mixed variable types (binary, categorical, skewed) with a separate model for each, which is why it is the workhorse in epidemiology.
How to read it
Check the trace plots: the chains should mix with no trend. Compare imputed with observed distributions: under MAR they may legitimately differ (older people’s values are imputed as older people’s values), but implausible values flag a bad model.
library(mice)
pred <- make.predictorMatrix(d)
pred[, "SEQN"] <- 0                        # the ID is not a predictor
imp <- mice(d, m = 30, predictorMatrix = pred, maxit = 20, seed = 2026)
plot(imp)                                  # trace plots: chains should mix
densityplot(imp, ~ log_nak)                # imputed vs observed
fit <- with(imp, lm(sbp ~ log_nak + RIDAGEYR + RIAGENDR))
summary(pool(fit), conf.int = TRUE)        # Rubin's rules

This builds 30 completed datasets with every other variable as a predictor (except the ID), checks convergence and the imputed values, fits the analysis model in each dataset and pools the results.

Trap

Single imputation: filling with the mean, the last value, or one regression prediction, then analysing as if the data were complete. Mean imputation shrinks variance and distorts associations; any single imputation treats guesses as data, so intervals are too narrow. The missing-indicator method (fill with 0, add a “was missing” dummy) is biased for confounders in observational studies.

From your ML background

scikit-learn’s IterativeImputer is modelled on MICE, but by default it returns one deterministic imputation: fine for a prediction pipeline, wrong for inference. Flexible imputers (random forests, missForest) give accurate point predictions yet too little spread, which understates uncertainty unless they are used inside a proper MI loop. In MI the goal is plausible draws, not the best guess.

4. What goes in the imputation model

Put in everything the analysis uses, including the outcome, plus auxiliary variables that predict the missing values or their missingness.

What it is
Three groups. Analysis variables: exposure, outcome, confounders, in the same form the analysis uses them. Auxiliary variables: not in the analysis but correlated with the incomplete variable or with being missing. Design variables: survey weights, strata and clusters (section 7).
Why it matters
Imputed values only reflect relationships the imputation model contains. Leave the outcome out and you impute an exposure that is unrelated to the outcome, which drags the estimate towards no effect.
How to read it
A good methods paragraph lists the imputation model’s variables, says the outcome was included, names auxiliaries and states m. An imputation model simpler than the analysis model (missing interactions, missing non-linear terms) biases those terms towards zero.
Trap

“Using the outcome to impute the exposure is circular.” It is not: the imputation draws exposures consistent with the observed joint distribution, which includes the outcome. Omitting it assumes the exposure–outcome association is zero for everyone with missing data, and that assumption is what biases the result.

Example · Project 3 auxiliaries

For missing urine Na/K, the 24-hour dietary recall sodium and potassium are natural auxiliaries: imperfect, but correlated with urinary excretion. Blood pressure and antihypertensive use help too. Keep in mind what the imputed variable is: a single spot-urine ratio, a noisy marker of usual intake (Lecture 2.14). MI fills in missing spot values; it does nothing about the measurement error in the values you have.

5. Rubin’s rules and how many imputations

The pooled estimate is the average across imputations; its variance adds the ordinary sampling variance to the disagreement between imputations.

What it is
With \(\bar W\) the average squared standard error within datasets and \(B\) the variance of the estimates between datasets, the total variance is \[ T = \bar W + \left(1 + \tfrac{1}{m}\right) B \] The \(1/m\) term pays for using a finite number of imputations.
Why it matters
\(B\) is the price of the missing data. If imputations disagree a lot, the data say little about the missing values and the interval widens to show it.
How to read it
The fraction of missing information is roughly the share of \(T\) due to \(B\). It is often smaller than the share of incomplete cases, because the other variables recover some information. A rule of thumb: m at least the percentage of incomplete cases (White, Royston and Wood), so 30% incomplete means about 30 imputations.
What a change means
Going from 5 to 50 imputations barely moves the point estimate but makes the standard error and p-value reproducible: rerun with a new seed and you get the same answer to the decimal you report.
Rubin’s rules: within, between and total variance

Each grey line is one imputed dataset’s estimate and interval. Raise the between-imputation spread (more missing information) or the number of imputations, and watch the pooled interval against the over-confident single imputation.

Trap

Averaging the m datasets into one and analysing that. Averaged imputations behave like single regression imputation: the between-imputation variance disappears and the standard errors are too small. Pool the results, never the data.

6. Ratios, transformations and interactions

When the analysis uses a derived variable such as the Na/K ratio, or an interaction, the imputation must respect it; otherwise the relationship you care about is diluted.

What it is
Passive imputation: impute sodium and potassium, then recompute the ratio from them inside every iteration, so ratio and components always agree. “Just another variable”: impute the ratio (or log ratio) directly as its own variable, so its relationship with the outcome is modelled directly, at the cost of consistency with the components. Substantive-model-compatible FCS (the smcfcs package) imputes in a way that is consistent with the analysis model, including non-linear terms and interactions.
Why it matters
Passive imputation models Na and K but not the ratio’s link with the outcome, which can attenuate the ratio’s estimate. Simulation studies find no simple method is best everywhere; smcfcs is the principled option when the analysis has non-linear terms or interactions.
How to read it
For interactions (say Na/K × sex), impute separately within each sex or include the product terms in the imputation model. Otherwise the imputed data carry no interaction and the estimate shrinks towards none.
meth <- make.method(d)
meth["nak_ratio"] <- "~ I(una / uk)"         # recomputed from imputed Na and K
pred <- make.predictorMatrix(d)
pred[c("una", "uk"), "nak_ratio"] <- 0        # Na and K are not imputed from the ratio
imp <- mice(d, method = meth, predictorMatrix = pred, m = 30, seed = 2026)

The ~ I(...) method tells mice to compute the ratio rather than impute it. The predictor-matrix line stops a circular loop in which the ratio would help impute its own components.

Example · why the ratio

One reason to use the sodium-to-potassium ratio from a spot urine is that both concentrations rise and fall with how dilute the sample is, so dilution largely cancels in the ratio. That makes the ratio a sensible exposure to analyse, and therefore a variable whose relationship with the outcome the imputation must preserve.

7. MI with survey weights and survival outcomes

The imputation model must carry the survey design and the survival outcome; for survival, use the event indicator and the cumulative hazard, not raw follow-up time.

What it is
Surveys: include the weights (or the variables that build them) and the strata and PSUs as predictors when imputing, then analyse each completed dataset with the full survey design and pool with Rubin’s rules. Survival: White and Royston (2009) showed the outcome is best represented by the event indicator plus the Nelson–Aalen estimate of the cumulative hazard at each person’s follow-up time; in their simulations, using raw or log time instead performed worse.
Why it matters
Ignoring the design in imputation can bias estimates for oversampled groups. Ignoring the survival outcome, or entering it badly, attenuates hazard ratios, which is exactly the estimate Project 3 reports.
How to read it
The Nelson–Aalen approach is an approximation that works best when effects are modest and events are not very common. With competing risks (Lecture 3.7), include an indicator and a cumulative hazard for each cause, or use smcfcs, which supports competing-risks models.
d$H0 <- nelsonaalen(d, fu_months, cvd_death)   # Nelson–Aalen cumulative hazard
pred <- make.predictorMatrix(d)
pred[, c("SEQN", "fu_months")] <- 0   # H0 and the event indicator stand in for time
imp <- mice(d, m = 30, predictorMatrix = pred, seed = 2026)  # d holds weights, strata
library(survey); library(mitools)
des <- svydesign(ids = ~SDMVPSU, strata = ~SDMVSTRA, weights = ~wt, nest = TRUE,
                 data = imputationList(complete(imp, "all")))
fits <- with(subset(des, RIDAGEYR >= 20),
             svycoxph(Surv(fu_months, cvd_death) ~ nak_ratio + RIDAGEYR + RIAGENDR))
summary(MIcombine(fits))                        # Rubin's rules, design-based SEs

The first three lines add the cumulative hazard, stop raw time and the ID from acting as predictors, and impute with the design variables in the data. The rest builds one survey design over all 30 completed datasets, subsets it to adults, fits the survey-weighted Cox model in each, and pools.

Trap

Imputing on the full file, then filtering each completed dataset to the analysis sample before building the design. That is the subsetting error of Lecture 3.4 repeated m times. Impute on everyone, build the design on each completed full file, then subset() the design.

Example · Saudi and GCC surveys

The same recipe applies to the Saudi Health Interview Survey or a GCC STEPS file. Region is part of the sampling design, and measurement completeness often differs by region (blood or urine samples are harder to collect and transport from remote areas). Put region, the PSU identifiers and the weight in the imputation model; otherwise imputed values are pulled towards the regions with the most complete data.

8. Sensitivity analysis for MNAR

Because MAR can’t be checked, show how far the answer moves if missing people differ systematically from similar observed people.

What it is
Delta adjustment: impute under MAR, then shift the imputed values by a chosen amount δ (“people with missing urine have Na/K about 10% higher than similar people with urine”), re-analyse and pool. Repeat over a range of δ. The tipping point is the δ at which the conclusion changes.
Why it matters
It turns an untestable assumption into a transparent statement reviewers can judge: “the hazard ratio stays above 1 unless missing participants’ ratios are more than 30% lower than observed participants like them.”
How to read it
Choose the δ range from evidence (who skips the exam, what non-responders are known to be like), not from what makes the result look stable. A large tipping point is reassuring; a small one means the result rests on MAR.
for (delta in c(-0.2, -0.1, 0, 0.1, 0.2)) {      # shifts on the log scale
  post <- make.post(d)
  post["log_nak"] <- paste("imp[[j]][, i] <- imp[[j]][, i] +", delta)
  imp_d <- mice(d, predictorMatrix = pred, post = post, m = 30,
                seed = 2026, printFlag = FALSE)
  fit_d <- with(imp_d, coxph(Surv(fu_months, cvd_death) ~ log_nak + RIDAGEYR + RIAGENDR))
  print(summary(pool(fit_d), conf.int = TRUE, exponentiate = TRUE)[1, ])
}

Each pass shifts every imputed log Na/K by δ (0.1 on the log scale is about 10% higher), re-imputes, refits and prints the pooled hazard ratio, so you can see where the conclusion tips. In the real analysis, swap coxph for the survey-weighted fit of section 7.

Trap

Writing “missing data were handled by multiple imputation” as if that settles it. MI handles MAR. The paper should also say why MAR is plausible and show at least one MNAR sensitivity analysis for the main exposure.

Check yourself

  1. In a cohort, income is missing for 25% of participants, mostly those with high incomes. Income is a covariate in a Cox model for cardiovascular death; nothing about death predicts whether income is missing once the model’s covariates are known. Is complete-case analysis biased for the exposure’s hazard ratio?

    Show answer

    No. Missingness depends on income itself (MNAR for income), but not on the outcome given the covariates, so CC is unbiased for the coefficients, just less precise. Standard MI under MAR could actually be biased here unless something predicts the missing incomes well. CC would be biased for the mean income, though.

  2. A colleague imputes missing urine Na/K using age, sex, BMI and blood pressure but leaves out death and follow-up “to avoid circularity”. What happens to the hazard ratio, and how would you fix it?

    Show answer

    It is biased towards 1, because imputed ratios carry no link with death. Add the event indicator and the Nelson–Aalen cumulative hazard to the imputation model (White and Royston 2009), not raw or log time.

  3. Five imputations give hazard ratios of 1.21, 1.35, 1.18, 1.40 and 1.25, each with a standard error of about 0.08 on the log scale. Is five enough, and what does the spread tell you?

    Show answer

    On the log scale the five estimates have a standard deviation of about 0.07, close to the within-dataset standard error, so the between-imputation variance is roughly half the total: a lot of information is missing. Five is too few for a stable standard error and p-value; use at least as many imputations as the percentage of incomplete cases, and check the result is stable across seeds.

  4. The analysis model includes a Na/K × sex interaction, but the imputation model has only main effects. What will the interaction estimate look like, and what should change?

    Show answer

    Shrunk towards zero, because imputed values were drawn as if the Na/K–outcome link were the same in both sexes. Impute separately by sex, add the product terms to the imputation model, or use smcfcs with the interaction in the substantive model.

  5. A paper reports an MI result and adds: “Little’s test, p = 0.4, confirmed data were missing at random.” What two things are wrong?

    Show answer

    Little’s test addresses MCAR, not MAR, and a non-significant result is not confirmation (it may simply lack power). MAR versus MNAR cannot be tested from the data. The paper should argue the mechanism from data collection and show a delta-adjustment sensitivity analysis.
