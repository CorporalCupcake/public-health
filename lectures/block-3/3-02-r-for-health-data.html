Lecture 3.2

Statistical computing in R for health data

Block 3 · Biostatistics core
The point

If you are fluent in Python, R is quick to write and easy to get subtly wrong. Three defaults decide what your results mean: how factors are ordered, how missing values spread, and how a model formula turns categories into columns. This lecture maps your pandas habits onto R, flags the traps that change estimates without an error message, and gives you the map of health packages you will use from Lecture 3.3 to Project 3 and beyond.

1. R’s data model for a Python user

In R everything is a vector, indexing starts at 1, and functions never change their arguments in place.

What it is
There are no scalars: 5 is a numeric vector of length one. Operations are vectorised by default. A data frame is a list of equal-length column vectors; a tibble is a stricter data frame that prints better.
Why it matters
Most R surprises for Python users come from three places: 1-based indexing with negative indices meaning “drop”, silent recycling of short vectors, and copy-on-modify semantics (a function that edits a data frame returns a new one; the original is untouched).
How to read it
If code works only because of recycling or a lucky index, it will break quietly on the next dataset. Prefer explicit joins and named columns over positions.

Trap

Using x[-1] to mean “the last value”. In R it returns everything except the first value, with no error. Write tail(x, 1) or x[length(x)].

From your ML background

R’s modelling functions take a data frame and a formula, not an X matrix and a y vector. The formula builds the design matrix for you, which is convenient and is also where the defaults in sections 2 and 6 bite.

2. Factors and their traps

A factor is a vector of integer codes with a table of labels, and its level order silently chooses your reference group.

What it is
R’s type for categorical variables. Internally, codes 1, 2, 3…; the levels attribute maps codes to labels. An ordered factor adds an order (low < middle < high).
Why it matters
Models turn a factor into dummy columns and compare every level with the first level. Tables list levels in level order. The default order is alphabetical, which is rarely the order you want.
How to read it
Before any model, run levels(x) and table(x, useNA = "ifany"). The first level printed is your reference.
What a change means
Changing the reference changes every coefficient and p-value for that factor but not the fitted values. The model is the same; the questions it answers are different.

Example · A column that became a factor

One cell of a blood-pressure column reads "128*", so the column is read as text and later turned into a factor. as.numeric() then gives the level codes 1 to 87. They are numbers, so nothing errors, but every summary built on them is wrong. Since R 4.0, text columns are no longer turned into factors on import by default, but packages and old scripts still do it.

Analogy

A factor is a coat-check system: you hold ticket 2, and the cloakroom’s list says ticket 2 is “Former smoker”. Do arithmetic on the tickets and you are adding cloakroom numbers, not coats.

3. Missing values: NA spreads, and survey codes hide

R’s NA means “unknown”, so anything computed from it is unknown too; survey files add a second problem, missing values disguised as numbers.

What it is
NA + 1 is NA, mean(x) is NA if any value is, and NA == NA is NA, so test with is.na(). na.rm = TRUE drops missing values from a summary. NULL is “nothing at all”, and NaN is an undefined number such as 0/0.
Why it matters
Each function handles NA its own way, and some silently drop rows. lm() and glm() discard every row with a missing value in any variable in the formula (complete-case analysis), so adding a covariate can change who is in the model. dplyr::filter() drops rows where the condition is NA. table() hides NA unless asked.
How to read it
Always report the number analysed: nobs(fit). If it differs between models, they are fitted to different people and cannot be compared directly. Lecture 3.5 covers what to do instead.
Operationpandas defaultR default

d <- d |> mutate(smq020 = replace(smq020, smq020 %in% c(7, 9), NA))  # 7 refused, 9 don't know

The first line sets NHANES’s “refused” and “don’t know” codes to missing for one smoking question. The codes depend on the field width (7/9, 77/99, 777/999…), so check each variable in its codebook rather than recoding every 7 and 9 in the file.

Trap

Missing values stored as numbers. In NHANES and most survey files, “refused” and “don’t know” are numeric codes, not NA. Left in, a 77 or 999 becomes a real value: an extreme drinker or an implausible income, pulling means and slopes. R cannot know; only the codebook does.

From your ML background

Your pandas reflexes are inverted. pandas skips missing values quietly in summaries, so you rarely see them; R refuses to give an answer, so you notice. R is noisier but safer: a summary that returns NA is telling you to decide how missing data should be handled, and that decision belongs in the analysis plan.

4. Tidyverse, base and data.table

Use dplyr for clarity, data.table or duckdb for very large tables, and base R where a package would be overkill; they mix freely.

What it is
The tidyverse (dplyr, tidyr, readr, ggplot2, forcats, lubridate) gives one verb per operation, chained with the pipe |> (built into R since 4.1; %>% is the older magrittr pipe). data.table is a fast, terse alternative: dt[rows, columns, by = groups]. Base R is what every package is built on.
Why it matters
Readable data preparation is reviewable data preparation (Lecture 3.1). For millions of rows, such as MIMIC-IV’s event tables, dplyr on a laptop becomes slow; data.table, or dplyr syntax running on duckdb or arrow, keeps it fast.
How to read it
Pick one style per project for data preparation. Mixing dplyr and data.table in one pipeline is legal but hard to review.

Trap

A many-to-many join. If the lab file has two rows for some participants (a repeat measurement), left_join() duplicates those participants and your sample grows. Recent dplyr versions warn about unexpected many-to-many matches; check row counts before and after every join anyway.

5. Dates and labelled survey data

Dates are numbers counted from an origin, and survey files carry numbers with labels attached; both go wrong when you forget which they are.

What it is
An R Date is days since 1 January 1970. lubridate parses (ymd(), dmy()) and measures (time_length(interval(dob, exam), "years")). haven reads Stata (read_dta), SPSS (read_sav) and SAS transport files (read_xpt, the NHANES format). Stata and SPSS columns arrive as labelled numbers: 1 with the label “Male”.
Why it matters
Survival analysis needs follow-up time, and survey analysis needs categories coded correctly. A date read with the wrong origin, or a region code treated as a number, gives a confident wrong answer.
How to read it
Convert labelled columns deliberately: as_factor() for categories, zap_labels() for true numbers. NHANES’s public linked mortality files give follow-up as person-months from interview and from examination, not as dates, so check which one matches your time origin.
demo  <- haven::read_xpt("data-raw/DEMO_J.XPT")      # NHANES 2017–2018 demographics
steps <- haven::read_dta("data-raw/steps.dta")      # labelled numbers: 1 = "Male", 2 = "Female"
steps <- steps |> mutate(sex = haven::as_factor(sex))
d <- d |> mutate(age = time_length(interval(dob, exam_date), "years"))
Trap

Different origins. SAS counts days from 1 January 1960, R from 1970, Excel from the end of 1899. Turn a raw SAS date number into an R date without the right origin and every date moves by ten years. haven converts properly formatted SAS and Stata dates for you; numbers that were never formatted as dates need the origin stated.

In the Gulf

Survey microdata, such as WHO STEPS (the Project 3 fallback) and DHS, often arrive as Stata or SPSS files with value labels, sometimes in Arabic. Files written by older software may store Arabic labels in the Windows Arabic code page; read_sav() has an encoding argument (for example "windows-1256") for that case. Check the labels print correctly before you trust any table.

6. Model formulas and contrasts

A formula is a compact recipe for the design matrix, and the contrast coding decides what each coefficient compares.

What it is
y ~ a + b reads “y is modelled by a and b”. R expands each term into columns: a number stays one column, a factor becomes dummy columns, a spline becomes several. Contrasts are the rule for turning a factor into columns: the default, treatment coding, compares each level with the reference; sum coding compares each level with the average of the level means.
Why it matters
The same data and model give different-looking coefficient tables under different codings and references. Reviewers read your table; they need to know what each row compares.
How to read it
Under treatment coding, the intercept is the reference group’s value and each coefficient is a difference from it (a log rate ratio or log odds ratio in a GLM). Check levels() to know which group that is.
What a change means
Changing contrasts changes coefficients, standard errors and p-values for that factor, but not the fitted values or the overall fit. If fitted values change, you changed the model, not the coding.
Factor and contrast explorer

Systolic blood pressure by smoking status. Start with R’s default (reference “Current”, because it comes first alphabetically). Switch the reference to “Never”, then try sum coding, then the numeric-codes trap. Watch what each coefficient means, and whether the fitted group means change.

Trap

Reading the intercept under sum coding as the overall mean. It is the unweighted average of the group means, which differs from the mean of all participants whenever groups differ in size. And sum coding leaves out the last level’s coefficient: it equals minus the sum of the others.

From your ML background

Treatment coding is one-hot encoding with the first column dropped (drop="first" in scikit-learn); the dropped level becomes the intercept. statsmodels formulas use the same default as R. A full one-hot encoding with an intercept is collinear, which a penalised ML model tolerates and an unpenalised GLM does not.

7. From model to table and figure: broom and ggplot2

broom turns any fitted model into a tidy data frame, and ggplot2 turns data frames into figures by mapping columns to visual properties.

What it is
broom’s tidy() gives one row per coefficient, glance() one row per model, augment() one row per observation. ggplot2 is a grammar: data, aesthetic mappings (which column goes to x, y, colour), geoms (points, lines, ranges), scales, and facets (small multiples).
Why it matters
Tidy output feeds tables (gtsummary) and figures directly, so the numbers in the manuscript come straight from the model (Lecture 3.1). Most packages you will use, including survival, survey and lme4 (via broom.mixed), have tidy methods.
How to read it
For a GLM, ask tidy() for exponentiate = TRUE to get odds or rate ratios, and conf.int = TRUE for intervals.
fit <- glm(cvd ~ smoke + ns(age, 4) + sex, family = binomial, data = d)
tidy(fit, exponentiate = TRUE, conf.int = TRUE) |>
  filter(term != "(Intercept)") |>
  ggplot(aes(x = estimate, xmin = conf.low, xmax = conf.high, y = term)) +
  geom_pointrange() +
  geom_vline(xintercept = 1, linetype = "dashed") +
  scale_x_log10()                       # ratios belong on a log axis

This fits a logistic model, extracts odds ratios with 95% intervals, drops the intercept, and draws a forest plot with a reference line at 1.

Trap

Plotting ratios on a linear axis. An odds ratio of 0.5 and one of 2 are equally strong effects in opposite directions, but on a linear axis the first looks half as big. Use a log scale for every ratio.

Check yourself

  1. After import, summary(as.numeric(d$sbp)) shows values from 1 to 94. What probably happened, and how do you fix it?

    Show answer

    The column was read as text (some cell was not a clean number) and turned into a factor, so as.numeric() returned level codes. Find the offending values, fix the import (or clean the text with code), and convert with as.numeric(as.character(x)) only after checking what will become NA.

  2. A logistic model of cardiovascular death on smoking reports rows smokeFormer and smokeNever, both with negative coefficients. What is being compared, and what would make the table easier to read?

    Show answer

    Both are compared with current smokers, the alphabetical first level: former and never smokers have lower odds than current smokers. Making “Never” the reference gives the usual epidemiological reading, the excess odds of current and former smoking. The fitted risks do not change.

  3. Model A for systolic blood pressure uses 9,812 participants; Model B adds income and uses 8,904. You present them side by side to show how much income “explains”. What is wrong?

    Show answer

    lm() dropped everyone missing income, so the models are fitted to different people. Any change in coefficients mixes the effect of adjustment with the effect of a different sample. Fit both to the same participants, and handle the missing income properly (multiple imputation, Lecture 3.5). Report nobs() for each model.

  4. Your dplyr summary of mean urinary sodium by smoking group shows NA for one group, and an extra row labelled NA. The same summary in pandas showed numbers for every group and no extra row. Explain both differences.

    Show answer

    R’s mean() returns NA if any value in the group is missing; pandas skips missing values by default. The extra row is participants with missing smoking status: group_by() keeps them as a group, while pandas drops missing group keys by default. R’s behaviour shows you two missing-data problems that pandas hid.

  5. Switching a factor from treatment to sum contrasts changes the coefficient for “Former” from 7.5 to 4.0 and its p-value. A coauthor asks which model is right. Answer them.

    Show answer

    Both: it is the same model with the same fitted values and fit. The coefficients answer different questions: Former versus the reference group, or Former versus the average of the group means. Choose the coding whose comparison you want to report, and say which one it is in the table.
